Does reasoning help?  ·  P2 viva

Offline Demo Run Sheet

Four commands, about three minutes, no network and no GPU. This is the running order, what each command puts on the screen, and what to say over it.

no API key needed no network runs in ~1 second each python scripts/demo.py

Before you walk in

All of this is quick, and doing it once the night before is the difference between a demonstration and a debugging session in front of a panel.

  • Open a terminal at the repository root Not P2/ — the git root, ragrobust/. Every path in the demo is relative to it.
  • Confirm the two large files are present data/cases/benchmark.jsonl (36 MB) and data/cache/generators.sqlite (72 MB). Both are gitignored, so a fresh clone will not have them.
  • Run pytest -q once 377 tests, about three seconds. It also proves the curated cases still resolve against the benchmark.
  • Do a dry run of all four commands The first run of anything is always the slow one. Do it before the room is watching.
  • Widen the terminal and raise the font The output is laid out for 96 columns. Below that it wraps and stops being readable from the back of the room.
  • Have the casebook open in a second tab It is the fallback if the terminal misbehaves, and it is the better artefact to leave with anyone afterwards. It is private until you share it from the page's share menu.

The sequence

Four beats, in this order. Each command finishes in about a second, so the pacing is set by what you say, not by what the machine does.

1

Opening · 20 seconds

Show that the whole run is on the laptop

$ python scripts/demo.py list

  Curated cases
  Each replays offline from data/cache/generators.sqlite. No network, no GPU, no API key.

  RQ1 refusal      python scripts/demo.py case refusal-unans-nq-2842
  The answer passage was removed. Reasoning answers anyway.
  …

Every model call this study made is in a content-addressed cache in the repository. So the experiment replays here, on this laptop, through the same pipeline objects that produced the results — with the models taken away. Nothing you are about to see is being generated now. Then pick the case you want and type it.

2

The RQ2 story · 60 seconds

One case, three pipeline classes, three different failures

$ python scripts/demo.py case conflict-nq-4643

  Question  when is the met office leaving the bbc
  Gold      31 March 2018

  The injected contradiction   diffed against the original passage
      original:  MeteoGroup is due to take over on 31 March 2018 …
      injected:  MeteoGroup is due to take over on 30 November 2017 …

  NAIVE       31 March 2018
              answer correct | CRS 0 — no acknowledgement of the conflict
  REASONING   The passages disagree on the date when the Met Office will leave …
              answer correct | CRS 4 — locates it and resolves it
  AGENTIC     INSUFFICIENT EVIDENCE  (abstained)
              classified refusal | CRS 0

The two passages are identical except for one date, and the demo diffs them so you can see exactly what was injected. All three systems saw the same two passages. The naive arm gives the right answer and never mentions that its evidence contradicts itself — correct under exact match, zero under the rubric. That gap is the whole reason RQ2 needed a rubric rather than an accuracy score.

The agentic arm decomposed the question, re-retrieved three times inside the sandbox, and abstained. More machinery, worse outcome, on this case.

3

The RQ3 story · 45 seconds

One question, five noise ratios, three shapes of degradation

$ python scripts/demo.py noise tqa-2481

  Question  Petroliam Nasional Berhad … gave its abbreviated name to what landmark?
  Gold      Petronas Towers

                         r=0.00    r=0.25    r=0.50    r=0.75    r=0.90  
  naive                  OK        OK        OK      ABSTAIN   ABSTAIN
  reasoning              OK        OK        OK        OK        OK  
  agentic                OK        OK        OK        OK       WRONG

Same question, same answer passage, buried under a rising proportion of distractors — measured in tokens, not passages, so the ratio on the axis is the ratio the generator actually sees. The naive arm stops answering at three quarters noise. Reasoning holds all five. The agentic arm holds four and then answers PETRONAS instead of Petronas Towers, which the string matcher scores wrong.

That last cell is limitation 15, live: some of the measured degradation is the scorer, not the model. I would rather show you that than have you find it.

4

The close · 35 seconds

Prove it is the real run and not a recording

$ python scripts/demo.py verify --n 200

  Coverage
      281 generator call(s) served from data/cache/generators.sqlite
      0 network calls — ReplayProvider imports no HTTP client and raises on a miss
      196/200 instances replayed to a final answer; 4 could not

  Provenance   the claim that matters
      196/196 replayed responses are byte-identical to a response this run recorded

  Reproduction
      190/196 reproduced this configuration's own stored record exactly (96.9%)
      68/68 unshared cache entries reproduced exactly

  PASSED  every response served came out of this run, and every departure
          from the stored record is accounted for.

Two hundred instances, drawn with a fixed seed, replayed in about a second. The provider that serves them imports no HTTP client at all, so being offline is structural rather than a promise — there is no flag I could have forgotten to set.

And it does not claim more than it can prove. It reports 96.9 percent, not 100, and the appendix explains the gap: the cache is keyed on the prompt rather than on the configuration, so two arms that rank a case identically share one entry. No reported number depends on it — scoring ran off the result records, where each arm kept its own response.

If a reviewer pushes

The three questions this demonstration invites. Answer the third one before it is asked, in step 4, and it stops being a challenge.

Isn't this just replaying answers you saved? How is it a demonstration?

The generators are replayed; everything else runs. The sandboxed corpus is rebuilt, BM25 ranks the passages, the agentic pipeline decomposes the query and re-retrieves inside the sandbox, and the response parser extracts the delimited answer — all in the same objects the experiment used. What is served from cache is the four evaluated generators, which are self-hosted at 7 to 9 billion parameters and cost GPU-minutes to wake. Replaying them is also more honest than calling them live: at temperature 0, batched inference is not bit-reproducible across batch compositions, so a live re-run could disagree with the thesis for reasons that have nothing to do with the argument.

Why is reproduction 96.9 percent and not 100?

The cache key covers the prompt and the decoding parameters, not the configuration that issued the call. Two configurations that build a byte-identical prompt therefore address one entry, and the run wrote both — the survivor is whichever finished last. It happens when the BM25 and dense arms rank a case's passages into the same order, and it always happens for the agentic decompose step, which is built from the query alone. Those instances are checked against both arms' stored records rather than excused, and every instance whose entry is provably unshared is held to byte-exact reproduction with no exceptions.

How do I know the agentic pipeline isn't retrieving from the open web?

It cannot. Every retrieval, including agentic re-retrieval, is confined to the case's own passage set plus a controlled distractor pool, and a distractor pool containing an answer-bearing passage raises rather than passes. That is the control that lets any agentic gain be attributed to orchestration rather than to better retrieval. The demo prints the passage ids each re-retrieval returned, so you can see they come from inside the sandbox.

Can I see a case you didn't choose?

Yes — demo.py case <case_id> takes any of the 2,858 cases in the benchmark, not only the curated eight. If they name a dimension rather than a case, the casebook is faster to navigate than the terminal.

Fallbacks

In the order you would reach for them.

If the terminal misbehaves, switch to the casebook.

It is one self-contained HTML file with 24 cases and 144 stored responses baked in — no server, no repository, no network. It shows the same evidence and the same responses, laid out as a matrix so the class effect and the model effect are both readable at a glance.

If a case prints “chain forked at the shared decompose entry”.

That is the shared-entry caveat, and it is only possible in the agentic class. The demo prints the answer that configuration actually recorded underneath it, so nothing is lost — but if you would rather it not appear at all, --generator 2 runs the same case on the other base model.

Do not reach for --retriever dpr on stage.

The dense arm needs a sentence-transformers model, which downloads on first use. BM25 is the default precisely so that nothing has to be fetched. Both are real experimental arms; only one is safe to run in front of an audience.

Command reference

Everything the demo takes. Run from the repository root.

CommandWhat it does
demo.py listThe curated cases, each with the command to run it and what it argues.
demo.py case <case_id>All three pipeline classes on one case: the evidence, the injected contradiction diffed, each arm's answer, its verdict, and the agentic sub-queries.
demo.py noise <seed_id>One seed across all five noise ratios as a grid — the Noise Degradation Curve, one seed wide. Takes tqa-2481, not noise-tqa-2481-r50.
demo.py verify --n 200Replays a fixed random sample and checks provenance, coverage and reproduction. Exits non-zero on anything it cannot account for.
--generator 1|2Which base model. 1 is Qwen3-8B, 2 is GLM-4-9B; both read from configs/models.yaml.
--tracePrints reasoning traces. Worth having ready — they are retained for qualitative analysis and never scored, and showing that is a good answer to a question about the reasoning arms.
--full-textPrints passages in full instead of the first few lines.
--no-colorPlain output, for piping into a file or pasting into a slide.
