Retrieval Failure Casebook

Twenty-four cases from a benchmark of retrieval-augmented generation under imperfect retrieval, each shown as six systems answered it. Every response below is the one the reported numbers were computed from.

The casebook

Each strip shows six configurations: three pipeline classes on each of two generators.

Where this comes from

Responses are read from runs/results.jsonl, verdicts from runs/scored.jsonl. Nothing on this page is regenerated, and no model is called: it is the stored record of a run of 34,283 scored instances.

Reading a case

Rows are the three pipeline classes; columns are the two generators. A difference down a column is orchestration. A difference across a row is the base model — which, across the full study, is the larger of the two.

Running it yourself

python scripts/demo.py case <case-id> replays any of these offline through the real pipelines, and demo.py verify checks that every response served came out of this run.
